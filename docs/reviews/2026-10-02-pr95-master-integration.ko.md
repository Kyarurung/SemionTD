# PR #95 master 통합 검증

사용자가 표시·오라·소환 수명·소환 가격 수정을 승인한 뒤 커밋·푸시와 master 병합을 요청했다. 기존 검수 기록의 후속 통합 결과다. 운영 배포는 포함하지 않는다.

## 기준 이력

- 병합 전 master: `706e3e6c6d532987e2eebe41f93a9eed5a2dc534`.
- 원본 PR #95: `5baf984e5593e9faadfb0da650a09991b2663312`.

- 작업 브랜치: `codex/pr95-display-aura-fixes`.
- PR 대상은 기존 `s3-release`에서 요청한 `master`로 변경했다. 원본 PR 커밋 이력은 보존했다.

## 충돌 처리

10개 파일의 충돌을 확인했다. 신규 기능의 방향을 다시 정해야 하는 충돌은 없었다. 이전 #93 이력을 다시 합치면서 master의 후속 수정이 되돌아가지 않도록 정리했다.

- 판다 돌진·구르기와 모델 애니메이션 초기화는 master 구현을 그대로 유지했다.
- 마왕·식물의 기존 수치와 런타임 변경을 유지했다. 방어력 감소 및 판다 외형 회귀 검사도 보존했다.
- 설계도 명령어, 가격·모듈 기본값, 수명·오라 수정은 작업 브랜치 구현을 포함했다.
- 정원사 선분 거리 계산은 원래 계산과 같은 공통 `LineTargets` 함수로 연결했다.
- 고정 빌더 스타터는 154개를 유지한다. 개인 설계 타워는 이 고정 목록과 별개다.
- 배포용 `tower_balance.json`은 master와 대조했을 때 `abilities.builder_blueprint`만 추가된다. 기존 빌더 수치는 바뀌지 않는다.
- PR의 이전 이력에 있던 Python 캐시는 최종 추적 파일에서 제외하고 로컬 파일은 보존했다. 로그·원본 경기 아카이브·빌드 결과는 커밋하지 않는다.

## 통합 과정에서 수정한 검사

첫 전체 실행은 GameTest 724개 중 카탈로그 수 검사 1개가 실패했다. 고정 스타터 154개에 병렬 실행 중인 하수인 수명 검사가 만든 개인 설계도 1개까지 세어 155개가 된 것이 원인이다.

`ArmyGameTest`와 `SemionParticipantGameTest`의 고정 스타터 수 검사에서 개인 설계도 ID만 제외했다. 기대 수를 155나 최소 개수 조건으로 바꾸지 않았다. 개인 설계의 등록·배치·재로드 유지·삭제는 기존 Blueprint 검사에서 계속 검증한다.

## 최종 검증

Java 21, 격리된 검수 작업 공간에서 실행했다.

- 수정한 카탈로그 GameTest 단독 실행: 1개 통과.
- `rtk ./gradlew test runGameTest remapJar --console=plain --no-daemon`: 전체 통과.
- JUnit: 총 1,454개 중 1,452개 통과, 기존 skipped 2개, 실패·오류 0.
- GameTest: 필수 724개 모두 통과.
- `remapJar`, `git diff --check`: 통과.
- 제출 검사 스크립트: 통합 커밋을 기준으로 오류·경고 0. 통합 커밋 전에는 공통 조상 기준으로 기존 모델까지 함께 집계되었으므로 그 중간 결과를 이번 신규 변경의 판정에 사용하지 않았다.
- master의 판다·마왕·타워 엔티티 및 식물 정의가 그대로 보존됐는지 파일 대조했다.

검수 스킬의 격리 병합·기존 동작 보존·전체 회귀 검증 절차를 적용했다. 자동 검증을 실제 클라이언트 화면 확인으로 취급하지 않는다. 실제 화면 확인, 운영 밸런스 입증, 라이브 JAR 교체, 서버 재시작, 웹 배포는 수행하지 않았다.
